## 최신 사용자 결정과 구현 전 가이드

2026-09-21 사용자는 장중 변화 시안을 선호한다고 확인하고, 기존 기능 정리부터 시작하는 구체적인 단계별 개발 가이드를 요청했다. 최신 실행 후보는 [선물 매크로 장중 변화 개편 PLAN](../../../tasks/active/futures-macro-intraday-redesign-20260921/PLAN.md)과 [DESIGN](../../../tasks/active/futures-macro-intraday-redesign-20260921/DESIGN.md)이다. **전체 5차, 개발 0/5이며 가이드 확인 후 별도 작업 요청 대기**다.

아래의 초기 3차안과 COMPACT_OUTLOOK_GUIDE의 일봉 과거 사례 중심 순서는 조사 이력이다. 현재 우선순위는 현재 관측/연구 실행 분리 → 마감 이후·최근 1시간 비교 → 해석 → compact 화면 → 통합 검증이다. 장중 과거 확률 연구와 M2 연구 모델 수리는 이번 5차의 필수 범위가 아니다.

## 사용자 목적 구체화에 따른 후속 가이드

사용자는 현재 강약 → 과거 같은 상황에서 다른 자산의 실제 움직임 → 조건부 큰 흐름을 간결하게 읽는 장치를 원한다고 명확히 했다. 이에 따른 최신 제안은 [COMPACT_OUTLOOK_GUIDE.md](./COMPACT_OUTLOOK_GUIDE.md)다. 아래는 최초 성능·가치 감사의 결론이며, 새 가이드는 실제 자산 forward return과 n/N·baseline을 연결하는 확장 범위를 다룬다. 두 문서 모두 구현 승인을 대신하지 않는다.

이후 계산 결과의 신빙성을 묻는 의도를 정정하고 [실제 예비 검증](./EMPIRICAL_PILOT_RESULT.md)을 수행했다. 고정한 국채 약세+달러 강세 조건의 5D 단순 빈도는 SPY/QQQ/TLT 모두 순차 평가에서 기준보다 낫지 않았다. 따라서 관측/과거 비교는 유지하되 ‘조건이 있으니 방향 전망을 제공한다’는 전제를 두지 않는다. 조건·자산·horizon별 우위 검증이 화면의 전망 문구보다 먼저다.

## 결론

현재 선물 매크로에는 유효한 가격 관측 정보가 있다. 가장 뚜렷한 자산군과 서로 다른 기간의 방향, 교차자산 확인 여부를 빠르게 볼 수 있다. 그러나 경제 원인 규명, 미래 방향의 확률 우위, 보유 포트폴리오의 성과 개선까지 확인된 도구는 아니다. 현 UI의 설명과 체제 라벨은 이 경계를 충분히 전달하지 못한다.

사용자가 느끼는 느림은 실제다. 최근 갱신 70.6초 중 57.8초가 snapshot materialization이다. 저장 입력의 read-only 재현에서 hidden 미래 5D/20D 검증만 약 60.3초였다. 현재 관측 중심의 사용자 목적과 클릭마다 조건부로 수행되는 무거운 shadow 연구 계산이 맞지 않는다.

현재 완료 snapshot의 예측 gate는 5D/20D 모두 NO_EDGE다. 5D는 무조건부 기준보다 Brier가 소폭 나쁘고 20D는 기준모형이 선택됐다. 따라서 이 계산을 기다리게 하는 비용에 상응하는 검증된 예측 가치를 주장할 근거가 없다. 다만 NO_EDGE를 이유로 가격 관측 기능 자체를 폐기할 필요는 없다.

## 사용자에게 주는 현재 정보

09-21 세션의 조사 당시 화면은 금리 부담만 1D/5D/20D에 걸쳐 뚜렷하고, 주가지수는 1D만 강하며, 다른 핵심축의 5D 동조는 약했다. ‘국채 약세와 금리 민감 자산을 먼저 확인하되 시장 전체 방향은 아직 확정하기 어렵다’가 가장 정직한 해석이다.

최근 체제 이력 60개 중 혼재 53개(88.3%)로, 하나의 색상 라벨이 너무 넓은 상황을 담고 있다. 저신호와 축 간 충돌, 현재처럼 특정 축만 두드러지는 상태를 사용자 언어로 구분할 필요가 있다. 임계값을 임의로 낮춰 색상을 다양하게 만드는 방법은 권하지 않는다.

## 후속 구현 제안

1. **1차: 갱신 경로 분리.** overview_actions / futures_macro_snapshot / 현재 pattern service를 중심으로 현재 관측을 빠르게 갱신하고 hidden 검증은 독립적으로 관리한다. 완료 조건은 현재 값·잠정/확정·날짜 경계를 보존한 parity와 실제 실행 시간 비교다.
2. **2차: 해석 흐름 개선.** futures_macro_helpers와 React workbench에서 ‘관측 → 의미 → 내 자산과의 관련성 → 다음 확인 조건’을 연결한다. 현재 사용자 사례로 이해도와 Browser QA를 확인한다. 새로운 진단 패널은 목표가 아니다.
3. **3차: 검증·데이터 계약 개선.** macro contribution 계약 불일치부터 해결하고 eligibility precheck, 중복 계산 재사용, 성능 최적화를 수행한다. 예측 가치는 별도 OOS·baseline 비교로 확인하며, 실제 보유자산 의사결정 유용성은 forward 수익/위험·비용까지 따로 평가한다.

1차는 속도를, 2차는 읽는 목적을, 3차는 정확성과 연구 효율을 다룬다. 실제 코드·UX 변경은 이 제안에 대한 사용자 결정을 받은 뒤 별도 task로 전환한다. 분석 요청 자체에 필요한 1~3차 조사는 모두 완료됐고, 미완료 분석 단계는 없다.

## 검증과 한계

코드 tracing, 실제 갱신 로그, SELECT-only 재현, 저장된 validation, 브라우저 DOM을 교차 확인했다. 애플리케이션 코드는 변경하지 않아 구현 회귀 테스트는 실행 대상이 아니다. 개선 후 속도, 전체 역사에 걸친 체제 가치, 실전 수익 개선은 검증하지 않았다. 상세 근거는 CURRENT_PROJECT_AUDIT / SOURCES / RISKS에 둔다.
